# 核心思想

AI 安全没有“银弹”。真正有效的体系建立在少数几个经过验证的原则之上，并在每一层技术栈中落地。

## 1. CIA + 安全（Safety）

传统信息安全强调机密性（Confidentiality）、完整性（Integrity）、可用性（Availability）。AI 系统还需要增加 **Safety**：

- **输出不应伤害用户或社会**：避免生成恶意代码、歧视性内容、危险指令。
- **行为可预期**：Agent 即使在开放环境中也应受策略约束，不会无限放大权限。
- **人在回路（Human-in-the-Loop）**：高风险决策保留人工审批。

## 2. 最小权限（Least Privilege）

每个主体——人类用户、服务账号、Agent、模型、工具——只应拥有完成当前任务所需的最小权限。

- **人类用户**：按角色隔离（RBAC）。
- **Agent / 工具**：按 capability 授权，避免“一个 Agent 能调用所有工具”。
- **模型**：限制可访问的数据集、向量集合、外部 API。
- **工作负载**：Service Account、Workload Identity、细粒度网络策略。

## 3. 纵深防御（Defense in Depth）

单一控制点失效是常态。AI 系统应在多个层面叠加防护：

```text
用户输入 → WAF/网关 → 身份认证 → 授权决策 → 输入 Guardrail → 模型/Agent → 输出 Guardrail → 审计日志 → SIEM
```

任何一层被绕过，下一层仍能降低损失。

## 4. 零信任（Zero Trust）

核心信条：**永不信任，始终验证**（NIST SP 800-207）。

- 不默认信任内网流量。
- 每次访问都基于身份、设备健康、上下文做动态授权。
- 微分段（Micro-segmentation）限制横向移动。
- 持续监测与假设 breach。

在 AI 场景中，零信任意味着：训练集群、模型仓库、推理服务、向量库、外部 API 之间的每一次调用都要验证身份与权限。

## 5. 安全左移（Shift Left）

把安全控制前置到设计、开发、训练阶段，而不是等到上线前扫描：

- **设计阶段**：威胁建模（STRIDE、OWASP LLM Top 10 2025、OWASP Agentic Top 10 2026、MITRE ATLAS）。
- **开发阶段**：依赖扫描、密钥检测、Prompt 模板审计、MCP Server 与工具描述审计。
- **训练阶段**：数据清洗、去标识化、后门/投毒检测。
- **部署阶段**：模型签名、镜像签名、最小权限网络策略、工具版本锁定。

## 6. 非人类身份治理（Non-Human Identity）

AI 系统中有大量非人类主体：

| 主体类型 | 身份形式 | 管理要点 |
|---|---|---|
| 人类用户 | SSO / OIDC | MFA、会话过期、审计 |
| 服务账号 | API Key、OAuth Client | 短效凭证、自动轮换、最小权限 |
| 工作负载 | SPIFFE/SPIRE、mTLS | 运行时身份、pod 级认证 |
| Agent | Capability Token（OAuth 2.0 Token Exchange，RFC 8693） | 按任务授权、时间窗口限制、委托链（`act`）可审计 |
| 模型/工具 | Signed Identity | 来源验证、调用范围限制、版本锁定 |

## 7. 可审计与不可抵赖

所有关键操作都应记录：谁、在什么时间、以什么身份、调用了什么模型/工具/数据、得到了什么结果。

- **审计日志**应 append-only、防篡改、可追踪。
- **决策记录**：授权决策、Guardrail 拦截、人工审批都需留痕。
- **模型/数据血缘**：训练数据、模型版本、部署配置的关系可追踪。

## 8. 安全与可用性的权衡

| 控制 | 收益 | 成本 |
|---|---|---|
| 强认证 + MFA | 降低账号接管 | 增加登录摩擦 |
| 输入/输出过滤 | 降低提示注入与有害内容 | 增加延迟、可能误判 |
| 细粒度授权 | 最小权限 | 策略复杂度、性能开销 |
| 零信任 mTLS | 防止横向移动 | 证书管理、调试复杂度 |
| 人类审批 | 高风险可控 | 降低自动化、增加人力 |

## 9. 意图与能力绑定（Intent-Capability Binding）

Agent 时代的特有原则：**模型"想做"什么（意图）和它"能做"什么（能力）必须在每次工具调用处对齐校验**，不能因为"它说了要调这个工具"就放行。

- **意图声明**：高风险操作要求 Agent 显式声明意图（如"发送邮件给 X"），网关/Guardrail 将其与请求的工具参数比对。
- **能力收窄**：为单次任务签发最小 scope 的短期 token，任务结束即失效（OAuth 2.0 Token Exchange，RFC 8693），避免 Agent 长期持有"万能凭证"。
- **委托链可审计**：Agent A 代表用户 U 调用 Agent B 时，凭证中应携带完整委托链（`act` 声明），任何一环越权都能被定位。

这是 OWASP ASI02/ASI03 的核心防御思想，也是 2026 年主流身份厂商（Okta Auth for GenAI、Microsoft Entra 等）产品化的方向。

## 10. 不可信上下文假设（Untrusted Context）

RAG 检索片段、网页抓取内容、工具返回结果、MCP Server 的工具描述、Agent 长期记忆——**这些进入上下文窗口的内容都应默认不可信**，与系统提示享有不同的信任级别：

- **指令分层**：系统提示 > 开发者消息 > 工具返回 > 用户输入 > 外部检索内容。下层内容试图覆盖上层指令时应被检测或剥离。
- **数据与指令分离**：检索到的文档按"数据"处理，不被允许改变任务目标；工具描述在注册时快照，运行时 diff 校验，防止 Rug Pull。
- **记忆写入审查**：进入长期记忆的内容要过 Guardrail，出记忆（被检索进上下文）时再过一次。

OWASP ASI06（记忆与上下文投毒）与 MITRE ATLAS 的 Agent 专项技术（2025 年新增）都把这条原则列为缓解措施的第一条。

## 11. 可验证计算（Verifiable Compute）

当算力本身成为多租户商品（GPUaaS、云上训练），"信任硬件而非运营方"成为新的防线：

- **机密计算**：NVIDIA CC 模式（H100/H200、Blackwell 全系）在 GPU 内加密 VRAM（AES-256-GCM），密钥由芯片内引擎生成、主机软件不可见；结合 CPU TEE（SEV-SNP/TDX）与远程证明（NVIDIA NRAS），租户可以验证"我训练的模型确实跑在没被篡改的硬件与固件上"。
- **证明驱动准入**：K8s 准入控制可以根据远程证明结果（TEE 状态、固件版本）决定工作负载调度到哪些节点。
- **代价**：大矩阵运算开销可低至约 3%，端到端约 5-15%，并丧失部分可观测性——是否开启取决于数据的敏感等级。

## 小结

AI 安全的核心不是“堵住所有漏洞”，而是**在不确定的开放输入面前，通过身份、策略、分层控制与可审计性，把风险降到可接受水平**。Agent 时代在这之上又叠加了三条新原则：意图与能力绑定、不可信上下文、可验证计算。下一章将这些原则映射到具体的分层架构中。
